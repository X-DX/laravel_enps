# M5 · Slice 5.1 — Assign PRAN Against Accounts — Explained for Beginners

> **What this slice gives you, in one sentence:**
> Search a finalized account, record its **PRAN** (the national NPS number) as a draft, then
> **finalize** the drafts in the list below — the same draft → finalize rhythm as accounts.

M5 has two parts: **Part 1 = PRAN** (this slice) and **Part 2 = Letters** (next).

---

## A. What a PRAN is

- **PRAN = Permanent Retirement Account Number** — the subscriber's **national** NPS number
  (12 digits, e.g. `110016825057`).
- It's issued by the **central** system (NSDL/PFRDA), **not** by this office. The office only
  **records** it against an account it already issued.

So this screen is: *take a finalized account → attach its PRAN.*

---

## B. The screen — `/accounts/pran` (three stacked sections)

Permission `entrysection.assign_pran_against_accounts`.

**① Search account** — type an **account number *or* name** → matching **finalized, active**
accounts appear (live, capped at 15) → click one. *(A small upgrade over the legacy "type the
exact account number", which doesn't scale to 33k accounts.)*

**② Add/Update PRAN form** — read-only account details (Name, Designation, **Treasury Location**,
DDO) so the operator confirms the person, then **PRAN No**, **Confirm PRAN No**, **PRAN
Appointment Date**, **NIRA Account**. Saving writes `save_flag = 'T'` (a draft). If the account
already has a PRAN, it opens in **Update** mode.

**③ Pending PRANs for finalize** — the drafts, with a **select-all header checkbox** and the
action bar **Excel · PDF · Finalize · Delete** — exactly the pattern from Pending Accounts (4e).

---

## C. The rules (data safety)

- Only a **finalized, active** account can get a PRAN (not a draft, not a closed one).
- PRAN is **12 digits, first digit 1–9** → `regex:/^[1-9][0-9]{11}$/`.
- **Confirm must match** (`same:pranNo`) — double-entry kills typos.
- **PRAN is globally unique** — enforced with
  `Rule::unique('pran_no','pran_no')->ignore($accountNo, 'account_no')`. The `ignore` is the
  trick: it lets you re-save **your own** account's PRAN without tripping the uniqueness rule.
- **Appointment date required**.

`account_no` is UNIQUE in `pran_no`, so **one PRAN per account** is guaranteed by the database.

---

## D. Two small design choices worth noting

- **No copying.** A PRAN row stores only PRAN-specific fields; **Name / DOB / Department come
  from the account** (joined via the `subscriber()` relationship) — one source of truth, same
  principle as the closure register.
- **Finalize is a flag flip.** Unlike accounts (where finalize *allotted a number* via a
  service), a PRAN finalize is just `save_flag → 'F'` + a date. That's trivial, so it lives
  right in the component — **no service needed** here. (Right-sizing: a service earns its place
  when there's real logic to isolate; a one-line bulk update doesn't.)
- `ddo_reg` is set to a fixed `'SGV183455B'` (the nodal office's NSDL registration), matching
  the legacy — flagged as a candidate for config later.

## E. How to verify yourself

```bash
php artisan test --filter=AssignPranTest
```

**Result:** 12 tests. They cover: the permission gate; search by number *and* name (drafts
excluded); select loads add-mode / pre-fills update-mode / rejects a closed account; the PRAN
validation (12-digit regex, confirm-match, date); **a duplicate PRAN is rejected**; a new draft
saves with the system fields; update keeps a single row; finalize flips drafts; **delete removes
drafts only**; and select-all. Full suite: **147 → 159 passing**.

Then on **/accounts/pran**: search an account, save a PRAN draft, watch it drop into the pending
list, and try Finalize / Delete / Excel / PDF.

---

## F. Gotchas worth remembering

- **`Rule::unique(...)->ignore(id, column)`** is how you enforce global uniqueness while still
  letting a record update itself.
- **Double-entry + a strict regex** is cheap, high-value protection for a number typed from a
  paper letter.
- **Don't build a service for a one-liner.** Finalize here is a bulk `update` — a component
  method is the right home.
- **Join, don't copy** — the PRAN row leans on the account for name/DOB/department.
